# 首次使用与 AI 配置

先完成 [安装](installation.md)，重新加载扩展后刷新 BOSS 岗位搜索 / 推荐页。以下说明适用于 Jev 求职助手 0.5.2.3。

## 先选择使用方式

筛选与招呼分别配置，基础条件始终先执行。

| 设置 | 作用 | 所需服务 |
| --- | --- | --- |
| 仅基础筛选 | 按已配置的结构化条件筛选岗位 | 无需 AI Key |
| Jev 筛选 | 按求职意向进行语义判定，可按契合度排序 | TypeSafe Key |
| 传统 AI 筛选 | 使用筛选提示词调用所选模型 | 已保存的模型服务 |
| 仅平台默认招呼 | 使用平台默认的首次沟通 | 无需 AI Key |
| 自定义消息 | 默认招呼确认成功后追加已配置内容 | 无需 AI Key |
| AI 追加招呼 | 默认招呼确认成功后生成并追加内容 | 已保存的模型服务 |

Jev Key 与大模型服务 Key 分开保存，额度分别计算。使用 Jev 筛选并不要求招呼也使用 AI。

## 四步开始

1. **统计 → 我的求职意向**：填写目标、简历、想要 / 避免的条件和严格程度，单独保存。PDF 提取在浏览器本地完成，需要 PDF 带文字层；提取后检查文字是否完整。
2. **AI → 岗位筛选方式 / 招呼方式**：根据上表选择。需要模型时先完成下方的模型保存；自定义消息在配置页编辑。
3. **检查并保存配置**：核对基础筛选、消息内容与每日上限，在统计页选择本轮上限和投递模式。本轮默认 50，首次建议设为 1–3。
4. **开始并观察**：确认将要联系的岗位与消息内容后开始。成功才计数，过滤和发送失败不占成功名额。遇到验证码或待核实状态，先检查平台提示和聊天记录。

## 快速、排序与额度

**快速模式（默认）**先读取详情并筛选，通过后逐条发送，同时提前判断下一条；只剩最后一个名额时不再提前判断。**排序模式**先筛选当前已加载批次，再按契合度从高到低投递，不足本轮目标时加载下一批。两种模式都保留原有发送与翻页间隔，不并发发送。

本轮成功目标与每日额度共同生效，每日最多 150，设置更低时以更低值为准。例如本轮目标为 50、每日上限为 150，而工具已记录今天成功 130 次，本轮最多再成功 20 次。工具统计不一定包含手机端或手动沟通；平台返回限额时仍会停止。

暂停后继续沿用本轮模式、目标和成功数；一轮结束后再开始才使用新目标。出现模型配置或额度错误时，先修正并保存对应服务，再选择「继续本轮」。本轮队列和判定展示保存在当前标签页内存；刷新页面会丢失同一轮续跑状态，已持久化的成功与去重记录仍保留。

默认招呼已经成功后，即使 AI 生成或追加消息失败，也保留成功记录。继续本轮不会自动为已联系岗位补发追加内容；发送结果未知时不自动重试，先人工核对，避免重复联系。

## 保存模型服务

1. 打开「管理模型服务」，添加或编辑服务，填写供应商、配置名称、接口基址、API Key 和模型名。
2. 点击「应用到草稿」；这一步尚未写入已保存配置。
3. 点击「保存模型配置」，再在使用该模型的筛选 / 招呼选项中选择它并保存配置。

取消编辑不改变已保存值；保存失败会保留草稿，修正后重新保存。切换供应商会清空旧 Key，需填写新供应商的密钥。求职意向、大模型服务和筛选 / 招呼设置分别保存。

模型名必须由对应服务支持，预设名称不代表当前账号有权限。接口基址按供应商文档填写，误粘 `/chat/completions` 会去掉该后缀，但不会擅自补 `/v1`。

### 兼容服务与 Gemini

可使用 OpenAI 兼容的 Chat Completions，也可在高级配置选择 Responses，并填写自定义接口地址。Gemini 能否通过某个兼容供应商使用，取决于该服务暴露的协议、模型名称和账号权限；只有模型名相同，并不意味着接口格式相同。不要将原生 Gemini 接口与 OpenAI 兼容接口混用。

高级配置包含 Responses、后台请求、超时、流式、传统筛选 JSON 和采样参数；测试与实际运行使用同一套设置。额外请求头和请求参数应填写 JSON 对象。工具调用不是本项目的使用场景。

「测试连接」由用户主动点击，发送一次最小请求，可能消耗额度。提示词测试也会发送岗位与提示词并消耗额度；打开配置页不会自动测试。测试尚未收尾时不能开始投递；后台请求取消需要等当前响应或配置超时收尾。

## 常见问题

| 现象 | 处理方法 |
| --- | --- |
| 额度不足、429 或服务限流 | 根据错误提示检查对应服务余额、套餐和限流；Jev 与招呼模型分别检查，修正后保存并继续本轮。 |
| 401 / 403 | 核对 Key、账号权限、所选模型和服务地址。 |
| 404 | 核对模型名、接口基址与 Chat Completions / Responses 类型。 |
| HTTP 200 但仍提示失败 | HTTP 成功不等于模型成功；检查提示中的流内错误、额度或服务错误，不据此认定招呼已发出。 |
| 空回复或返回结构不兼容 | 检查供应商支持的协议和流式格式；依据其文档调整设置再手动测试，不要反复开始真实投递。 |
| 网络或跨域失败 | 核对网络与地址，按需在高级配置启用后台请求，再手动测试。 |
| 不支持强制 JSON | 传统筛选可关闭「强制 JSON」，仍需提示词产出正确格式；该选项不影响 Jev。 |
| 找不到「继续本轮」 | 确认是否刷新过页面或换了标签页；刷新后不能恢复旧队列。 |
| 另一个标签页正在运行 | 在那个标签页暂停并等待收尾，同源标签页不能同时投递。 |
| 手动读取详情被阻止 | 暂停并等待读取收尾后重试；已加载详情仍可查看。 |
| 分数接近门槛却未通过 | 按实际分数比较；命中「避免」条件仍可能一票否决。 |
| 某条条件未命中 | 不等于明确不符合；服务未返回逐条原文依据，仅凭概率无法区分未提及和不符合。 |

公司 / HR 去重从新版成功发送开始记录相应标识。旧记录只有岗位 ID 时，无法补出历史公司的全部身份；历史岗位去重仍然保留。

## 分享与个人备份

「分享配置」只保留通用额度、延时和结构化过滤设置，不带简历、密钥、自由提示词或消息。模型分享会清空 Key 与额外请求头 / 请求体；分享前仍应检查自定义服务地址是否适合公开。

「个人备份」包含敏感信息，仅供本人恢复。求职 / 筛选 / Jev 配置与大模型服务分别备份。导入先进入草稿，需要明确保存；不要把个人备份或原始日志上传 GitHub。存储与清理说明见 [PRIVACY.md](../PRIVACY.md)。

反馈问题时提供扩展与浏览器版本、模式、复现步骤和脱敏错误；涉及凭据泄露等安全问题时，按 [SECURITY.md](../SECURITY.md) 报告。
